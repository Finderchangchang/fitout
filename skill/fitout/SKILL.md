# 装上就能出站

你在给一家公司做静态官网。版面在样板间里。你负责问答、把事实存进站点目录、自己写 `site.json`、跑一条命令、把首屏和交付说明交出去。

不调用 DeepSeek，也不要向用户要 `DEEPSEEK_API_KEY`。生图密钥没有就不要加 `--gen-images`，加了脚本也会跳过并提示。

命令在精装仓库根目录跑。下文这个目录叫「这里」。程序打印的成功句和报错是中文，以那一行为准。

## 红线

1. 事实只来自企业档案。档案没写的电话、微信、邮箱、备案号、价格、人数、年份、证号、评价原话、人名，不要补。
2. 不编数字。档案里的数字原样留着，不要换算，不要凑整。
3. 必须实拍的图片位不用生成图去顶。命令自己会避开。不要改 `images.json` 把 `mustBeReal` 改成 false。
4. 不替用户发布。不要 git push，不要打开 GitHub 去创建 Pages，不要替他点保存。
5. 不碰密钥。不要把密钥写进档案、命令参数、聊天记录或交付说明。不要向用户要密钥。
6. 不改 `framework/`、`scripts/build.mjs`、`scripts/check*.mjs`、`scripts/lib/`、`showrooms/`。站看起来不对，先看交付说明和机检原文。

## 站点目录

一个站点一个目录。不要写进 `framework/` 或 `showrooms/`。默认放在「这里」的 `out/<站点id>/`。

| 路径 | 内容 |
|---|---|
| `企业档案.md` | 问答确认后的事实，结构跟 `docs/PROFILE.md` |
| `site.json` | 你按 `docs/SITE_JSON.md` 写的站点内容 |
| `photos/` | 用户给的照片、二维码 |
| `img/` | 脚本放处理后的图 |
| `site/` | 生成的网站，`site/index.html` 是首页 |
| `交付说明.md` | 脚本写的交付说明 |

改内容 = 改 `企业档案.md` 或 `site.json`，再跑同一条命令。

## 按这个顺序做

### 1. 问要不要先看样板间

先问一句：要不要先看样板间。

用户要看：读 `showrooms/index.json`。每套给出 `name`、`fit`，以及预览图 `showrooms/` 加上该套的 `preview`（例如 `showrooms/cn-dining/preview.jpg`）。不要把十套一股脑贴完，先给跟用户那句话最接近的 2 到 3 套；用户说都看看，再按这份清单给全。

用户说先做：跳过，进入下一步。

### 2. 一问一答，存档，等确认

没有企业档案就按 `docs/PROFILE.md` 问。一次 3 到 5 个问题，最多三轮。不要把模板里每一格一次问完。

优先问：品牌名（练习或虚构，名字后加「（虚构）」）、行业、城市和地址、电话、营业时间。然后是主营和真实价格（没有价格让用户说不标价）、能公开的数字和团队人名、招不招加盟。用户没答的写「待补」或留空。不要用常识填。

整理成 UTF-8 的 `企业档案.md`，结构跟 `docs/PROFILE.md` 一样。中文 Windows 不要用 `echo >` 写文件。把全文给用户看。用户明确说可以了，再往下。用户还在改，就停。

### 3. 推荐样板间

按档案里的行业，从 `showrooms/index.json` 推 2 到 3 套，每套写 `id`、`name`、为什么适合、预览图路径。请用户选一套。用户不选，就用你推荐的第 1 套，并说一声。

### 4. 再问三件事

档案确认之后，一次问完这三件。答案写进 `企业档案.md` 第 10 节。

1. 首屏用轮播，还是一张大图。默认轮播。用户没意见就用轮播。
2. 要不要二级菜单。档案里能分开的品类不少于 2 个时，推荐自动用这些分类，并说出会挂在哪一项下面。用户要自己指定，就给出一份菜单（哪一项下面有哪些子项），等确认或改完再往下。品类不到 2 个，说明不需要，仍问一句。
3. 有没有二维码图片。有就把文件放进 `photos/`，并问每张旁边写什么字。没有就空着，不要编。

写进 `site.json` 时，以 `docs/SITE_JSON.md` 为准：

- 首屏写在首页 hero 板块的 `data` 里。`mode` 不写或写 `carousel`。`slides` 建议 3 到 5 张，引擎最多收 9 张。每张必填 `image`、`imageAlt`（样板间氛围图位按它的 `images.json`，`imageAlt` 照该位的 `desc` 原样抄）。某一张可以另写 `title`、`lead` 和按钮；没写就用首屏那一组。用户要一张大图：`mode` 写 `single`，或只留一张。顶层 `hero` 只放 `buttons`，不要把 `mode` 和 `slides` 写到顶层。
- 二级菜单：不写 `children` 时，这一项的链接对得上某个集合的列表页，并且该集合至少有 2 个分类，就自动生成。整份关掉写成 `{ "autoChildren": false, "items": [ ... ] }`。某一项 `"autoChildren": false` 只关这一项；写成集合 id 就指定用哪个集合。用户确认过的结构写在该项的 `children`：`[{ "label", "href" }]`。写了就用这份，不再自动生成。品类仍写在集合条目的 `category` 上。
- 二维码写 `contact.qrcodes`。数组，每项 `{ "image", "label" }`，`imageAlt` 可无。有则页脚最多 2 个，电脑右侧悬浮条多一个「二维码」。没有就不要这个键。联系板块的 `qrs` 是另一处，不要混用。`contact.wechatQr` 仍是微信号旁边那一张，不是页脚这组。
- 深色或 `image` 板块可以写 `bg`（放在板块上，或放在 `data.bg`），值是图片位 id。没图就退回纯色。首屏和内页横幅不要写。
- 集合列表页条目会超过一页时，在该列表板块的 `data.pageSize` 写每页条数。不写就是 9，最大 60。`data.limit` 只截首页导读，不拿来分页。

### 5. 自己写 site.json

读 `docs/SITE_JSON.md`，再读这套样板间的 `showrooms/<id>/examples/site.json`（只看结构）、`showroom.json`（页面、板块顺序、可选页的「什么情况下该有」）、`images.json`（图片位 id）。

把 `<站点目录>/site.json` 写出来。公司名、电话、价格、句子用档案里的，不要抄示例站。档案写「待补」、空着、或明确说没有的，整段不要。可选页对不上就 `"enabled": false`，导航不要指向它。不写颜色，不写 CSS。

### 6. 跑一条命令

在「这里」执行。`--showroom` 用用户选的 id。

```powershell
node scripts/fitout.mjs --profile <站点目录>\企业档案.md --out <站点目录> --showroom <id> --fill agent
```

照片已经在 `<站点目录>\photos\` 里就不用再加 `--photos`。要补氛围图才加 `--gen-images`。没有生图密钥时脚本会跳过并提示，不要为此停下来找密钥。

成功：退出码 0，有一行「交付：」，后面是站点目录。同一目录有 `交付说明.md`。

失败：退出码不是 0。第一句是「失败在「某一步」」。

失败在「填内容」并且下面是编号的校验清单：只改清单里的错，改 `site.json`，不要新增事实，然后重跑同一条命令。不要从半成品里挑一页当交付。

### 7. 交给用户看的两样

1. 首屏截图。有 Playwright 时，文件在 `<站点目录>/首屏-1440.png`。没有就让用户打开 `site/index.html`。
2. `交付说明.md` 里这几段：用了哪套样板间、开着和关掉的页、哪些图是实拍 / 生成 / 缺、机检、上线前要补的实拍、怎么发布。

不要把整站 HTML 贴进聊天。

### 8. 之后改哪里就改哪里

用户说换样板间：改 `--showroom`，按新样板间重写 `site.json` 里对不上的结构，同一条命令重跑。不要手改 CSS。

用户说改某句、某个价格、某个板块：先改 `企业档案.md` 里对应的事实（口号只改档案里的口号），让用户看一眼，再改 `site.json` 里那一处，重跑。不要为了改一句去重写整站。

## 退出码

| 情况 | 退出码 |
|---|---|
| 有「交付：」，机检 0 失败 | 0 |
| 档案缺行业、电话或别的必填项；参数写错 | 2 |
| 还没有 site.json，或校验、拼装、机检、视觉没过 | 1 |

`--fill agent` 不会因为没有 DeepSeek 密钥而失败。退出码 2 时还没有站点。退出码 1 时，目录里可能有半成品，不要拿去发布。

## 常见报错

| 看到的报错 | 怎么处理 |
|---|---|
| 失败在「读档案」 | 按列出的每一项问用户。不要编一个电话或行业去凑 |
| 还没有 site.json | 按第 5 步写好再跑 |
| 校验没过（N 条） | 按编号清单改 `site.json`，不要新增事实，重跑 |
| 没有这套样板间 | `--showroom` 改成用户选的 id |
| 跳过生图 | 正常。没有生图密钥。站点继续拼 |
| 必须实拍的位不能生图 | 这是对的。跟用户要照片，放进 `photos/` |
| 跳过统一调色 | 站点还能看。装好 Playwright 后再跑一遍才调色 |
| 机检没过 | 只看失败，不看警告。改档案或 site.json 后重跑 |
| 视觉检查：不通过 | 把失败原文给用户看。不要改框架去压过去 |
| 没有「交付：」 | 出站没完成。不要把目录里的 html 说成已经交房 |

`--fill deepseek` 才读 `DEEPSEEK_API_KEY`，那是命令行批量用法，见 README 的「进阶」。用户没要求批量时，不要改用这个模式，也不要让他把密钥贴过来。

## 安装

仓库放在本机任意目录。下文把这个目录写成 `<精装仓库目录>`。命令里的「这里」就是这个目录。不要把密钥文件放进仓库。

让助手找到这个 skill：把 `<精装仓库目录>\skill\fitout` 整个文件夹拷出去，文件夹名保持 `fitout`，里面要有 `SKILL.md`。

Claude Code：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.claude\skills" | Out-Null
Copy-Item -Recurse -Force "<精装仓库目录>\skill\fitout" "$env:USERPROFILE\.claude\skills\fitout"
```

Codex：同样拷到 `$env:USERPROFILE\.codex\skills\fitout`。

Grok：同样拷到 `$env:USERPROFILE\.agents\skills\fitout`，或 `$env:USERPROFILE\.grok\skills\fitout`。

拷完新开一轮对话。用户说「给我公司做个官网」「做官网」「建个网站」时，助手应读到本文件。仓库如果换了位置，把 `<精装仓库目录>` 换成实际位置，再拷一次。
