# 一句话出站

你在给一家公司做静态官网。版面在样板间里，你负责问清楚、整理档案、跑一条命令、把首屏和交付说明交出去。

命令在精装仓库根目录跑。下文这个目录叫「这里」。程序打印的成功句和报错是中文，以那一行为准。

## 红线

1. 事实只来自企业档案。档案没写的电话、微信、邮箱、备案号、价格、人数、年份、证号、评价原话、人名，不要补。
2. 不编数字。档案里的数字原样留着，不要换算，不要凑整。
3. 必须实拍的图片位不用生成图去顶。命令自己会避开。不要改 `images.json` 把 `mustBeReal` 改成 false。
4. 不替用户发布。不要 git push，不要打开 GitHub 去创建 Pages，不要替他点保存。
5. 不碰密钥。不要把 `DEEPSEEK_API_KEY`、`MINIMAX_API_KEY` 写进档案、命令参数、聊天记录或交付说明。缺密钥就让用户自己设环境变量。
6. 不改 `framework/`、`scripts/build.mjs`、`scripts/check*.mjs`、`scripts/lib/`。站看起来不对，先看交付说明和机检原文。

## 按这个顺序做

### 1. 没有档案就问

先看用户有没有给企业档案（一份 Markdown）。没有就按 `docs/PROFILE.md` 问，一次问最关键的 5 到 8 项，不要把模板里每一格都问完。

1. 品牌名。练习或虚构，名字后加「（虚构）」。
2. 行业和细分。例如社区奶茶、紧固件工厂、口腔诊所。
3. 城市和地址。
4. 电话。有微信就一起问，没有就写空。
5. 营业时间。
6. 主营产品或服务，以及真实价格。没有价格就让用户说不标价。
7. 能公开的优势、数字、团队人名。没有就空着。
8. 招不招加盟，几家店。一句首屏口号，没有就空着。

用户没答的项写「待补」或留空。不要用常识填。

整理成 UTF-8 的 Markdown，结构跟 `docs/PROFILE.md` 一样。中文 Windows 不要用 `echo >` 写文件。把档案全文给用户看。用户明确说可以了，再跑下一条。用户还在改，就停。

### 2. 跑一条命令

在「这里」执行。`--out` 用一个新目录，不要写进 `framework/` 或 `showrooms/`。

```powershell
node scripts/fitout.mjs --profile 企业档案.md --out ..\fitout-out\这家 --showroom auto
```

有老板照片（文件夹里是 jpg 或 png）：

```powershell
node scripts/fitout.mjs --profile 企业档案.md --out ..\fitout-out\这家 --showroom auto --photos D:\照片
```

照片文件名如果就是图片位 id（例如 `hero-tea.jpg`），会直接对上。对不上时，命令会按画面说明再问一次模型。

要补氛围图时才加 `--gen-images`。最多 8 张，且不会落在必须实拍的位。没有 MiniMax 密钥就不要加这个开关。

成功：退出码 0，有一行「交付：」，后面是站点目录。同一目录有 `交付说明.md`。

失败：退出码不是 0。第一句是「失败在「某一步」」。只处理这一步，不要从半成品里挑一页当交付。

### 3. 交给用户看的两样

1. 首屏截图。有 Playwright 时，文件在 `<输出目录>/首屏-1440.png`。交付说明的「首屏截图」里写这个相对路径。没有 Playwright 就让用户打开「交付：」那一行里的 `index.html`。
2. `交付说明.md` 全文里的这几段：用了哪套样板间、开着和关掉的页、哪些图是实拍 / 生成 / 缺、机检、上线前要补的实拍。

不要把整站 HTML 贴进聊天。

### 4. 用户只改两样

用户说换样板间：把 `--showroom auto` 换成交付说明里推荐的另一套 id，同一条命令重跑。不要手改 CSS。

用户说改首屏口号：只改档案里的「口号」那一节，让用户再看一眼，然后同一条命令重跑。不要在 `site.json` 里单独改一句。

别的句子、价格、人数，都回到档案里改，再重跑。

## 退出码

| 情况 | 退出码 |
|---|---|
| 有「交付：」，机检 0 失败 | 0 |
| 档案缺行业、电话或别的必填项；参数写错；没有密钥 | 2 |
| 挑样板间、填内容、配图、拼装、机检或视觉失败 | 1 |

退出码 2 时还没有站点。退出码 1 时，输出目录里可能有半成品，不要拿去发布。

## 常见报错

| 看到的报错 | 怎么处理 |
|---|---|
| 失败在「读档案」 | 按列出的每一项问用户。不要编一个电话或行业去凑 |
| 没有这套样板间 | `--showroom` 改成 `auto`，或改成推荐列表里的 id |
| 没有 DEEPSEEK_API_KEY | 让用户在环境变量里设置。不要问他把密钥贴过来 |
| 没填成 | 把括号里的几条原样留给下一次。不要手改 site.json 的数字 |
| 要生成图片，但没有环境变量 MINIMAX_API_KEY | 去掉 `--gen-images`，或让用户自己设密钥 |
| 必须实拍的位不能生图 | 这是对的。跟用户要照片，用 `--photos` |
| 跳过统一调色 | 站点还能看。装好 Playwright 后再跑一遍才调色 |
| 机检没过 | 只看失败，不看警告。改档案后重跑 |
| 视觉检查：不通过 | 把失败原文给用户看。不要改框架去压过去 |
| 没有「交付：」 | 出站失败。不要把目录里的 html 说成已经交房 |

## 安装

仓库放在本机任意目录。下文把这个目录写成 `<精装仓库目录>`。命令里的「这里」就是这个目录。不要把密钥文件放进仓库。

让助手找到这个 skill：把 `<精装仓库目录>\skill\fitout` 整个文件夹拷出去，文件夹名保持 `fitout`，里面要有 `SKILL.md`。

Claude Code：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.claude\skills" | Out-Null
Copy-Item -Recurse -Force "<精装仓库目录>\skill\fitout" "$env:USERPROFILE\.claude\skills\fitout"
```

Codex：同样拷到 `$env:USERPROFILE\.codex\skills\fitout`。

Grok：同样拷到 `$env:USERPROFILE\.agents\skills\fitout`，或 `$env:USERPROFILE\.grok\skills\fitout`。

拷完新开一轮对话。用户说「做官网」「建个网站」「给这家做个门户」时，助手应读到本文件。仓库如果换了位置，把 `<精装仓库目录>` 换成实际位置，再拷一次。
