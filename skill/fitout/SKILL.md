# 把企业资料做成客户看得懂的官网

交付的是一整套静态网站。配色和版式由样板间维护，你负责理解业务、填写内容、安排素材、运行生成器、看真实页面。用用户正在使用的助手完成填写，不调用另一个付费模型。

## 找到仓库

安装副本旁边有 `runtime.json` 时，先读里面的 `repository`，验证该目录有 `scripts/fitout.mjs` 和 `showrooms/index.json`。命令在这个仓库根目录运行。

手工复制安装、没有 runtime.json 时，先检查当前工作目录。仍找不到才问一次仓库位置，不要猜本机盘符。仓库移动后重跑安装命令。

## 事实和边界

- 只使用用户允许公开的事实。电话、价格、年份、人数、规格、资质、人名、评价原话都要有档案来源；不知道就省略。
- 数字保留原值，不为让企业显得自然而改数字。事实相互矛盾时指出对应原文，先收起矛盾内容。
- 实拍、图库、生成图分清。人像、门头、厂区、证书和客片需要真实素材，不能拿生成图冒充；`mustBeReal` 的限制不改。
- 不改生成器、样板间、配色或检查规则。可选页和板块没有内容就关闭，缺图用已有的无图版。
- 默认交付本地文件；只有用户明确要求发布时才发布。发布只使用 `site/`，企业档案、原始照片和本地配置不上传。
- 不索要密钥，不把密钥写进聊天、命令、档案或说明。默认 `--fill agent`。

## 1. 先理解企业与客户

用户已有档案、菜单、产品清单或介绍时先读，不重复问。

优先补清三件事：做什么、主要客户是谁、希望访客看完做什么（询价、预约或到店）。缺基本资料时，每次合并问 3–5 项；电话、地址和营业时间是当前生成器的必填项，不能编造。

事实整理到一个站点一个目录：默认 `out/<站点id>/企业档案.md`，格式读 `docs/PROFILE.md`。把整理后的事实和还缺的关键项给用户看；用户已确认过的资料直接沿用。

## 2. 推荐样板间与页面

读 `showrooms/index.json`，结合业务和目标推荐最接近的 2–3 套，附名字、适合的理由和预览图。用户明确选过就直接使用；让你决定时用第一推荐，不再多问一轮。

读所选样板间的 `showroom.json`。主要产品、关于和联系组成基本站；新闻、加盟、团队等只有资料支持才开。默认首页展示业务、产品、可核实能力和联系入口。不要把每个可用组件都放上去。

语言默认跟所选样板间的示例；用户指定语言时按用户选项。中文资料可以填英文站，数字和参数不换算。

轮播、菜单和二维码根据内容安排，不让老板先决定技术细节：有 3–5 张合适氛围图才用轮播，一张用 single，没有图直接用文字版；至少两个实际品类才推荐下拉菜单；有二维码文件才展示。

## 3. 整理素材

读所选 `images.json`。用户给了普通文件名的照片时，用助手的看图能力辨认用途，不要求用户改图片位编号。保留原照片，用副本整理到站点目录的 `photos/`。

`photos/sources.json` 可沿用 id 对应来源的写法，也可写既有交付清单结构：

```json
{
  "items": [
    { "id": "hero-tea", "file": "茶杯照片.jpg", "source": "photo" }
  ]
}
```

`source` 只能是 `photo`、`stock`、`ai`；`file` 是 photos 目录里的文件名；`id` 必须来自所选图片清单。确认画面含义后再分配。相同文件不重复分配到多个位置。

没有照片就完成精简无图版。助手有现成生图能力、且用户需要氛围图时，可以生成不冒充本企业实拍的氛围图，并按 `ai` 记录；不要求用户另配密钥。二维码和证书没提供就不显示。

## 4. 填写 site.json

读 `docs/SITE_JSON.md` 和所选板块的字段规格。示例只参考结构，企业事实来自档案。可以先看字段骨架，再填自己的内容；不要复制示例文案后逐句换公司名。

- 公司名、联系方式、产品、价格、规格、时间与档案逐一对应。
- 每个板块承担一个任务。没有新信息就合并或省略，首页不要重复宣传同一件事。
- 可选页不成立就 `enabled: false`，导航和按钮不要留关闭业务的入口。
- `mode` 和 `slides` 在首页 hero 的 data 里，顶层 hero 只放按钮。
- 同时按客户目标填写顶层 `buttons.primary`、`buttons.secondary`、`buttons.form`，设置全站默认行动文案；`hero.buttons` 只控制首页。逐个看详情页和表单按钮，关闭加盟的单店不能沿用招商文案。
- `lang` 明确写 `zh-CN` 或 `en`。英文按英文规则填，不硬套中文长度；图片说明选 `descEn`，没有则用该位已有说明。
- 列表默认 pageSize 9，少量产品不为了展示分页拆页。集合分页时引擎生成完整分类页。
- 日期、价格没有来源就省略对应字段；不要把“未定价”等施工状态写到网站。需要价格的首页菜单只收已确认价格的条目。二维码、证书没有有效文件就收起区域；产品缺图使用文字版。没有真实新闻不编一组新闻。
- 不写颜色和 CSS，不在 site.json 添加 page-banner，详情由集合生成。

## 5. 生成

在仓库根目录执行，路径有空格时加引号：

```powershell
node scripts/fitout.mjs --profile "<站点目录>/企业档案.md" --out "<站点目录>" --showroom <id> --fill agent
```

图片已经在 photos 不用加参数；外部照片目录可以加 `--photos "<照片目录>"`。语言要覆盖现有配置时加 `--lang en` 或 `--lang zh-CN`。

退出码 0 且有“交付：”才表示生成完成；`交付说明.md` 写页面、素材和检查状态。退出码 1 按错误清单修内容，退出码 2 补输入信息；保留机检原文，不用修改检查规则来压过去。

## 6. 看整站并验收

有浏览器工具时，用 1440 和 375 看首页、主列表、一个详情和联系页；新闻有内容时再看新闻列表、详情。除首屏外也要向下看完整页面。

检查访客是否能看懂业务、挑到产品、核对关键信息并找到联系入口。核对图文是否相符、数字是否一致、无图版是否仍完整、手机是否好读；实际点一次导航、分类、分页和联系按钮。电话和外部表单只验证链接，不替用户发送消息或提交信息。

有 Playwright 时生成器会做机检和视觉硬伤检查；仍要人工看图。没有浏览器时照常交文件，但如实写“尚未视觉验收”，不能报告视觉通过。

交给用户：网站首页入口，桌面和手机截图，已开/关闭的页面，素材缺口和来源，以及 `交付说明.md`。不用把 HTML 贴进聊天。

## 7. 之后修改

用户改一句话、价格或营业时间时，更新档案对应事实和 site.json 对应字段后重跑，不重新编整站内容。补照片时更新照片清单，保留原件。换样板间时按新页面结构调整 site.json。

站点目录：`企业档案.md` 是事实，`site.json` 是内容，`photos/` 是素材，`img/` 是处理后的图，`site/` 是网站，`交付说明.md` 是交付记录。

## 安装

仓库根目录运行 `node scripts/install-skill.mjs --target codex`。Claude Code 用 `--target claude`，其他兼容助手用 `--target agents`。安装后新开对话。

手工安装也可以：把 `skill/fitout` 整个文件夹复制到助手的 skills 目录，首次使用告诉助手仓库位置。
